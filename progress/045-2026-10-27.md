### Session 045 — 2026-10-27 — Fix ./init.sh always failing on the #23 placeholder test

- Goal: `./init.sh` exited 1 on every run since b77ec83 (found while bootstrapping ai-issue-triage with `create-harness`). Fix it upstream so adopters get it through `harness-upgrade`.
- Completed:
  - Root cause: `init.sh` runs `CW_INIT_SH=1 node scripts/framework-check.mjs verify-chain`. The test layer's `run()` helper in `tests/framework-check.test.mjs` spread `process.env` into each spawned runner, so the runner inherited `CW_INIT_SH=1`, lint only warned on unfilled docs, and "a fresh create-harness output fails lint and arch-003 (#23)" saw exit 0 instead of 1. The test passed alone and under `npm run check`, where the variable is not set.
  - Fix: `run()` now deletes `CW_INIT_SH` from its copy of the inherited environment before applying the test's own `env`. The neighbouring "init.sh's CW_INIT_SH warns instead of failing" test passes it explicitly and still passes.
  - Checked the only other spawn helper in `tests/` (`run()` in `tests/harness-docs.test.mjs`): it spawns the docs generator and `lint:command-surfaces`, neither of which reads `CW_INIT_SH`, so it is unaffected and left unchanged. Recorded as D-032.
- Verification run: `CW_INIT_SH=1 node --test --test-name-pattern="ensureNoPlaceholders" tests/framework-check.test.mjs` — failed 1/3 before the fix, passes 3/3 after. `./init.sh` and `npm run check` both exit 0.
