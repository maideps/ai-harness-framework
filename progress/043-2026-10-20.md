### Session 043 — 2026-10-20 — feat-022 Honest required-layer verification and private adopter package identity

- Goal: fix the two framework-level gaps a 2026-09-08 external review of a downstream adopter (ai-driven-marketing-ae-ce) traced upstream — a required verification layer could go "passing" while reporting only SKIP, and `create-harness` copied the framework's own npm package identity (and public `publishConfig`) verbatim into every new adopter.
- Completed:
  - `scripts/framework-check.mjs`: `verify-feature` now classifies a layer that exits 0 as "vacuous" when it reports `[SKIP]` with no real pass evidence — recognizing both this file's own `PASS:` convention and the nested `[PASS]` convention. A vacuous required layer (the default) now fails instead of silently passing; `"required": false` opts a layer out. A SKIP alongside real PASS output (the ruff/go/rust adoption-matrix cells) stays informational, unchanged.
  - `templates/multi-repo/verify-all.mjs`: applies the same rule per repository, with one carve-out — `repositories/example` is placed in every adopter unconditionally at `create-harness` time (the "optional component" markers are descriptive, not a copy gate), so an untouched scaffold placeholder alone must not fail a freshly-adopted repo. Only a real (non-scaffold) repository that never produces a pass now triggers the failure.
  - `scripts/create-harness.mjs`: `adopt()` now rewrites a freshly-created (not pre-existing) adopter `package.json`'s identity fields — sanitized name from the target directory, `version: "0.1.0"`, `private: true`, no `publishConfig`/`repository` — while leaving `scripts`/`bin`/`engines` as copied from the framework. An already-customized adopter `package.json` is never touched. The `create-harness` CLI also now reminds the adopter to review/replace the copied MIT `LICENSE` if their content isn't MIT.
  - Recorded D-029 and D-030 in `DECISIONS.md`.
  - Added tests: `tests/framework-check.test.mjs` (required-layer-fails-on-vacuous-SKIP, required:false opts out, mixed PASS+SKIP stays informational, the `PASS:`-vs-`[PASS]` convention case, plus a fixture fix for a test that unknowingly relied on the old lenient behavior) and `tests/create-harness.test.mjs` (new file: fresh adopter gets a private/sanitized identity, an existing package.json is never rewritten, name sanitization). Extended `scripts/adoption-matrix.mjs`'s `runMultiRepoTest` with: a pristine-scaffold-passes check, and a negative case where every repository is unconfigured SKIP and `verify-all` must fail.
- Debugging along the way (both caught by re-running the full suite before trusting the fix):
  - First pass only recognized the `[PASS]` bracket convention; `npm run check` itself emits the colon `PASS:` convention at its own level while containing nested `[SKIP]` lines, so every adoption-matrix cell's Layer 3 started failing. Fixed by recognizing both conventions.
  - Second pass then failed every adoption-matrix cell's `verify-all` outright, because `repositories/example` turned out to be placed in *every* adopter unconditionally, not only when the multi-repo component is deliberately activated as assumed. Fixed by excluding the untouched scaffold placeholder from the failure trigger.
