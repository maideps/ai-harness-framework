### Session 056 — 2026-11-05 — Harness self-tests leave the per-feature path in adopters (feat-029)

- Goal: in a new adopter, `verify-feature` took 215 s for a feature with no code and `npm run check` 203 s, almost all of it the harness testing itself (runner unit tests in `test`, adoption matrix in `e2e`). Move that out of the per-feature path without losing the check that the harness works on the adopter's machine.
- Sprint contract: build `frameworkRepository` detection, adopter `test`/`e2e` behavior, a `selftest` mode run by `verify-chain`, and the matrix's one shipped self-test run; verify with the four test files in Layer 0 plus the standard layers; success is a fresh adopter's `verify-feature` in seconds with this repository's own `test`/`e2e` unchanged. Risks: leaking the flag into adopters through create-harness or harness-upgrade; nested `node --test` runs that silently skip.
