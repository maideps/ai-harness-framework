### Session 044 — 2026-10-26 — Fix four dogfooding-reported GitHub issues (#23, #24, #25, #26)

- Goal: close out four open GitHub issues filed while bootstrapping an unrelated project (ai-codebase-auditor) with this harness — all real gaps found by actually using `create-harness`/`init.sh`/`npm run check`, not hypothetical.
- Completed:
  - **#26 — `.harness/trails/` vanishes on a fresh clone.** `create-harness`'s `createRuntimeSurfaces` now writes `.harness/trails/.gitkeep` alongside the existing `.harness/traces/.gitkeep` (git doesn't track empty directories, so an adopter who never ran `vcr` had no `trails/` on a fresh clone, failing `check-arch`'s manifest check). `harness-upgrade` backfills the same file for an already-adopted repo whose `trails/` directory is still empty, via a new `ensureTrailsGitkeep`.
  - **#23 — the placeholder check had gone silently vacuous.** `ensureNoPlaceholders` no longer matches five bracketed marker strings that drifted out of the templates' prose in an earlier rewrite (commit 461a042); it now diffs each checked doc (`README.md`, `docs/PRODUCT.md`, `docs/quality-document.md`) against its own manifest-declared template source, normalizing line endings. Fails `npm run check`/`npm run lint` and arch-003 with one line per unfilled doc. `init.sh` sets `CW_INIT_SH=1` so this specific check warns instead of failing on a project's first run (docs haven't been touched yet), while a manually-run `npm run check` and arch-003 stay hard gates.
  - **#24 — the multi-repo component was placed in every adopter unconditionally, and `verify-all` could silently pass having verified nothing.** `create-harness`/`placeTemplates`/`adopt` now take a `components` list; an optional component's templates (matched against the manifest's `optionalComponents[].markers`) are skipped unless requested. The CLI exposes `node scripts/create-harness.mjs <dir> --with multi-repo`, idempotent via the existing `skipExisting` contract, which is now also the documented way to activate it later. `templates/multi-repo/verify-all.mjs` gained a reserved exit code (`SKIP_EXIT_CODE = 42`) for its three "ran, nothing to verify yet" paths; `scripts/framework-check.mjs`'s `runVerifyAll()` recognizes it and reports `[SKIP] verify-all ran but nothing was verified yet` instead of an implicit pass. Recorded as D-031, which also documents superseding D-029/D-030's "optional is descriptive, not a copy gate" framing.
  - **#25 — replacing a layer script silently drops the harness's own checks, and the `e2e` cost/skip variable wasn't documented.** `scripts/harness-audit.mjs` gained `missingSelfChecks`, which flags (as a `[WARN]`, not a failure) a `lint`/`typecheck`/`test`/`build` script that no longer invokes `node scripts/framework-check.mjs <layer>` at all — chaining (`... && eslint .`) is not flagged. `docs/ARCHITECTURE.md` and both `docs/USAGE.md` (this repo's own instance doc and the generic adopter template under `templates/docs/USAGE.md`, which needed the same fix since it's what every future adopter actually receives) now explicitly document the chaining pattern as supported, with a worked example for all four layers, plus the `e2e` layer's real cost and `CW_SKIP_ADOPTION_MATRIX=1` to skip it locally. The same two `USAGE.md` files, plus `docs/ARCHITECTURE.md` and the manifest's `optionalComponents[0].description`, were updated for #24's opt-in behavior.
  - New tests: `tests/harness-upgrade.test.mjs` (trails backfill, and leaving an already-populated `trails/` alone), `tests/create-harness.test.mjs` (plain adoption places no optional-component files, `components` opts one in, re-running `placeTemplates` against an existing adopter only adds what's missing), `tests/framework-check.test.mjs` (the reserved SKIP exit code vs. a real failure, three placeholder-check cases including the `CW_INIT_SH` warn-only path), new file `tests/harness-audit.test.mjs` (`missingSelfChecks`, four cases). `scripts/adoption-matrix.mjs`'s `runMultiRepoTest` now builds a plain adopter first and asserts it has no multi-repo directories and that `verify-all` reports the component as not activated, then activates it through the real `placeTemplates({ components })` path instead of a hand-rolled copy loop.
